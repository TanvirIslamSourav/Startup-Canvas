# API Reference — Startup Canvas

> REST · `/api/v1` · OpenAPI 3.1 · Swagger UI at `/docs`

The schema below is a **stable contract**. The full machine‑readable spec is generated by FastAPI at runtime (`GET /api/v1/openapi.json`).

---

## 1. Conventions

- **Base URL**: `/api/v1`
- **Content type**: `application/json; charset=utf-8`
- **IDs**: opaque UUID v4 strings
- **Pagination**: `?page=1&page_size=20&sort=-updated_at&q=foo`
  - `page` 1‑based, default 1
  - `page_size` 1–100, default 20
  - `sort` field name, optional `-` prefix for DESC; whitelist per router
  - `q` free‑text search on the module's primary text columns
- **Errors**: JSON body `{ "error": { "code": "...", "message": "...", "details": {...} } }`, HTTP status reflects the failure.
- **Idempotency**: `POST` endpoints accept `Idempotency-Key` header.

### Error codes

| Status | Code                  | When                                       |
| ------ | --------------------- | ------------------------------------------ |
| 400    | `validation_error`    | Request body or query failed validation    |
| 401    | `unauthenticated`     | Missing/invalid credentials (future)       |
| 403    | `forbidden`           | Authenticated but not allowed (future)     |
| 404    | `not_found`           | Resource doesn't exist                     |
| 409    | `conflict`            | Uniqueness violation                       |
| 422    | `unprocessable_entity`| Pydantic validation failed                 |
| 500    | `internal_error`      | Unhandled server error                     |

## 3. Ideas

```
GET    /ideas                       list ideas (paginated)
POST   /ideas                       create idea
GET    /ideas/{idea_id}             get one idea
PATCH  /ideas/{idea_id}             update idea
DELETE /ideas/{idea_id}             soft‑delete idea (is_archived=true)
POST   /ideas/{idea_id}/duplicate   duplicate idea (returns new idea)
POST   /ideas/{idea_id}/restore     restore from archive
GET    /ideas/{idea_id}/summary     dashboard summary for one idea
```

#### List query params

| Param        | Type    | Notes                                  |
| ------------ | ------- | -------------------------------------- |
| `page`       | int     | default 1                              |
| `page_size`  | int     | default 20, max 100                    |
| `sort`       | string  | one of `created_at`, `-created_at`, `title`, `-updated_at` |
| `q`          | string  | full‑text on title/problem/solution    |
| `status`     | string  | filter by status                       |
| `category`   | string  | filter by category                     |
| `tag`        | string  | filter by JSONB tag                    |
| `archived`   | bool    | default false                          |

#### Schemas

```jsonc
// IdeaCreate
{
  "project_id": "uuid",
  "title": "string (1..200)",
  "problem": "string?",
  "solution": "string?",
  "audience": "string?",
  "category": "string?",
  "tags": ["string"],
  "status": "draft|validating|planned|building|launched|paused",
  "priority": 0
}

// IdeaUpdate — all fields optional, same constraints

// IdeaRead
{
  "id": "uuid",
  "project_id": "uuid",
  "title": "string",
  "problem": "string|null",
  "solution": "string|null",
  "audience": "string|null",
  "category": "string|null",
  "tags": ["string"],
  "status": "string",
  "priority": 0,
  "score": 0,
  "is_archived": false,
  "archived_at": null,
  "created_at": "iso8601",
  "updated_at": "iso8601"
}

// Page[IdeaRead]
{
  "items": [...],
  "page": 1,
  "page_size": 20,
  "total": 123
}
```

## 19. Schema mirroring (TS ↔ Pydantic)

To keep the frontend in sync without a code generator, every schema has a hand‑written mirror in `frontend/src/types/api.ts` plus a Zod validator in `frontend/src/features/<module>/schema.ts`. The mirror is the **contract**; if you change one, change both in the same PR and add a note to the CHANGELOG.
